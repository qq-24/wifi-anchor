# wifi-anchor · 探针版 v0.2-probe

室内 Wi-Fi 定位 App 的**第 0 步**。它不做定位，只做一件事：把「这台手机 + 这栋宿舍楼」的
真实条件量出来，然后我们据此决定正式版走哪条路。

技术方案与判据见 [SPEC.md](SPEC.md)。

## v0.2 相对 v0.1 的变化（由首轮实测驱动）

首轮实测（小米 23127PN0CC / Android 16）已经定案：**手机侧无 `FEATURE_WIFI_RTT`，且 71~76 台可见 AP 里
0 台宣告 802.11mc(FTM) 响应器** → RTT 通道在本楼关闭，正式版走指纹 + 连接 RSSI 心跳。
实测还暴露了两个必须改的事实，v0.2 已处理：

1. **采样会话原来只读缓存**，而本机不主动扫描时缓存约 24 秒才前进一次 → 连拍 40 帧里约 5/6 是同一份缓存的重复读。
   现在按实测的 **4 次/2 分钟**配额节奏主动挤扫描（28 秒一次），并用 `ScanResult.timestamp` 去重，
   界面上分开显示「已录帧数」和「其中几次是真刷新」。
2. **同一位置站着不动，可见 AP 数在 50~76 之间跳**（信道轮转）。这条不改代码，但它决定了正式算法必须按
   每台 AP 的跨帧出现率加权、且用多帧并集判定 —— 记进 SPEC §5.1。

另：新增会话「备注」字段（门开/关、手机在手还是放桌上），两项非公开 API 的读数改为如实标注原因。

## 一、装

1. 下载 Release 里的 APK（7.9 MB，debug 签名）。
   v0.2 直链：`https://github.com/qq-24/wifi-anchor/releases/download/v0.2-probe/wifi-anchor-probe-v0.2.apk`
2. 手机上打开该文件安装 → 需要允许「安装未知来源应用」。
   - 用系统浏览器或 **Chrome** 下载最稳；微信/QQ 内置浏览器常拦 apk，可「用其他浏览器打开」。
3. 首次启动会弹两类授权，都要给：
   - **精确定位**（不给就读不到 Wi-Fi 扫描结果，这是 Android 10+ 的硬规定）
   - **附近的设备 / NEARBY_WIFI_DEVICES**（Android 13+）
4. **系统定位开关必须打开**（设置 → 位置 → 开启）。Android 9 起，关掉它 Wi-Fi 扫描恒空，
   App 不会报错、只会给你空数据 —— 这是最容易踩的坑。App 内「总览」页有检测与跳转按钮。

## 二、测（大约 20 分钟，可以分几次做）

### 第 1 步：总览页 → 按「开始一键体检」（约 90 秒）
站在**你自己宿舍房间里**做。跑完点「复制全部」，把文本发我。
这一段能直接回答：手机支不支持 RTT、宿舍 AP 有没有开 FTM、扫描配额真相、缓存会不会自己刷新。

### 第 2 步：扫描页 —— 两个按钮各点一次
- 「12 次连发」→ 复制那段 `startScan 逐次结果`
- 「跑 3 分钟」被动观察（如果是 Android 13+，再加测「监听 5 分钟」）
这两段决定正式版后台常驻能做到多快、多省电。

### 第 3 步：采样页 —— 录点位（最重要，决定能不能分辨「房间 vs 同层厕所」）
每个点位站住不动，按「开始录制」，等它跑完再换地方。顺序建议：

1. `宿舍-桌前`
2. `宿舍-床边`
3. `同层厕所`
4. `走廊`
5. `楼梯口`
6. 随便一间**别的楼层**的房间（验证跨层会不会混）

**同一个点位要在不同时间再录一次**（早/午/晚，最好隔一天）。跨时间能不能复现是这条路的生死判据，
只在一个下午录全的数据算不出阈值。录的时候顺手记一句当时状态（门开着/关着、你在不在房间里）。

### 第 4 步：导出页 → 「存成文件」
存成一个 `.jsonl` 发我（整包都合并进去了，一次就够）。文本太长时用「只复制体检结果」也够我判断大方向。

## 三、要留意的假信号

- **FTM 台数为 0** 有两种解释：宿舍 AP 真没开，或者那一帧是旧缓存。先看「扫描」页确认能拿到新数据，再下结论。
- **缓存年龄（age）** 列如果显示负数或几小时，说明这台机器的 `ScanResult.timestamp` 语义和预期不同，
  该列忽略，改用「被动观察」的刷新次数判断新鲜度。
- **没连宿舍 Wi-Fi** 时，「已连接 RSSI 心跳」测不到东西（显示读不到），这是正常的；但这条通道
  是正式版省电的关键，请在**连着宿舍网络**的状态下测一次。
- 前台服务开关只用于对照实验：挂着它跑一遍配额实测，看限流有没有放宽。

## 四、构建（本机）

```
cd D:\mingh\Documents\wifi-anchor
./gradlew assembleDebug          # 产物 app/build/outputs/apk/debug/app-debug.apk
```

- 已在本机 `gradle.properties` 里固定 `org.gradle.java.home=D:/jdk17/jdk-17.0.13+11`：
  默认 JAVA_HOME 是 JDK 23，而 Gradle 8.9 不支持在 JDK 23 上运行。换机器请改这行。
- 版本组合刻意与 `Moniter_apk_plus` 一致（AGP 8.3.0-rc02 / Kotlin 1.9.0 / Compose BOM 2023.08.00 /
  compileSdk 34 / minSdk 24），全部依赖已在本机 Gradle 缓存内，**不引入任何新依赖**。
- 项目路径保持纯 ASCII：中文或 `==` 路径会让 Gradle 阶段挂掉（这是这台机器上踩过的坑）。
- 已知取舍：本机 `compileSdk 34` 的 `android.jar` 里**没有** `android.net.rtt.*`（新版 RTT API），
  只有 `android.net.wifi.rtt.*`，所以测距走 `WifiRttManager` 这个旧入口（Android 12+ 运行时仍提供）。
  若某台 ROM 把旧入口删了，App 会在 RTT 页显示「取不到 WifiRttManager」而不是崩。
